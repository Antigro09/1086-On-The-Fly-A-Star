`frc-field-map/1` is the shared local field-image and raw physical geometry document. The A* importer owns the schema and golden fixture. Custom-Vision consumes the same document read-only for its field view. It does not change perception calibration, localization, AprilTag layouts, live detections or robot state.

The JSON shape is in [frc-field-map-v1.schema.json](../schemas/frc-field-map-v1.schema.json). Runtime validators additionally check finite numbers, image bounds, affine determinant, ring winding and intersections, holes, metric bounds, residuals and content approval. A shape-valid JSON document alone is insufficient for planning or approval.

- `schema_version` is the literal `frc-field-map/1`.
- `map.id` identifies the map; `map.revision` is a positive integer for this content. `season` is nullable and does not select a controller toolchain. `variant` distinguishes field variants. `frame` is fixed `wpilib_nwu` and `units` is fixed `m`. `width_m` is the field **+X extent**; `height_m` is **+Y extent**. The coordinate origin is `(0,0)` and the extents are `(width_m,height_m)`. This revision is separate from a live producer's field-layout revision.
- `image.file_name` is a local basename, not a URL or directory path. `sha256` identifies exact encoded image bytes. Dimensions describe encoded pixels, with `u` right and `v` down. Accepted MIME types are PNG, JPEG and WebP. Attribution is required; an unknown license is `null`. The image file is separate from the JSON.
- `source` describes whether the document is synthetic, a user image, or verified official geometry. A URI is provenance text only; the importer and consumer do not fetch it.
- `calibration.model` is `affine`. `image_to_field` contains nine row-major entries. For image pixel `(u,v)`, field metres are `x=m[0]*u+m[1]*v+m[2]`, `y=m[3]*u+m[4]*v+m[5]`. Bottom row must be exactly `[0,0,1]`; the 2×2 determinant must be nonzero. Perspective/homography import is unsupported in this release. The top-down wizard solves uniform scale, orientation and origin using two distinct known floor-plane references; generic affine configurations can be imported and validated. Elevated structure/tag points are not floor-plane references.
- `control_points` contain `{pixel:[u,v],field_m:[x,y]}` used in the fit. `independent_check_points` use the same shape and must be distinct from fitted pixels. At least one independent check is required for whole-map approval. `fit_error_m` and `independent_check_error_m` are **RMS Euclidean projected residuals in metres**, each computed on its own point set: `sqrt(mean((projected_x-known_x)^2+(projected_y-known_y)^2))`. The runtime recomputes non-null residuals and rejects disagreement over `1e-8 m`. Unset/unperformed errors are `null`; an empty independent set cannot declare a residual. The UI requires independent error at most `max(0.05 m, 0.005*field_diagonal_m)` before applying calibration. This is a local review threshold, not a physical accuracy qualification. Imported residuals are displayed/validated, with review still required; consumers may impose stricter application thresholds.
- `distortion` records `uncorrected`, `corrected` externally, or `not_applicable` for a diagram. This importer does not estimate lens distortion. A top-down photograph with appreciable distortion requires correction before trustworthy metric use.
- `boundary.outer` and obstacle `outer` rings are explicitly closed, nondegenerate, counter-clockwise metric rings. `holes` are explicitly closed clockwise rings strictly inside their own outer ring, without intersections or overlap. Repeat the first point at the end. Geometry must stay within metric field extents. Obstacles remain raw physical geometry: no robot radius, clearance or uncertainty inflation belongs in this document.
- Each polygon has `review:{state:'draft'|'approved',reviewed_revision:null|integer}` and `provenance:{kind:'suggested'|'manual'|'verified_source',label,uri:null|string}`. Each obstacle also has a unique `id` and `vertical_range_m:null|{min,max}`. A known range requires finite `min < max`; **unknown heights remain null**, never zero. A 3D consumer should show unknown-height geometry as uncertain outlines instead of inventing solids.
- Whole-map `approval` binds to the exact content revision and digest. Image/calibration/geometry edits increment the revision, reset every polygon review to draft and clear whole-map approval. Reviewing one polygon does not increment the revision; changing its coordinates does. Approval creates a local sandbox map, with no live-state or robot-control authority.

The approval `content_sha256` is SHA-256 of UTF-8 canonical JSON of the complete document **excluding only the top-level `approval` key**. Object keys are recursively sorted by Unicode code point; schema keys are ASCII. Array order is preserved. Strings use JSON escaping and require well-formed Unicode (unpaired surrogate code units are rejected); booleans and null use ordinary JSON. Every number is encoded as a quoted string `"f64:"` followed by 16 lowercase hexadecimal digits of its big-endian IEEE-754 binary64 representation; normalize negative zero to positive zero before encoding. No whitespace is emitted. Thus numeric `1` and `1.0` have the same canonical form, and per-polygon reviews/provenance remain part of the digest. Validate revision-bound polygon reviews and declared residual consistency in addition to the digest. A copied digest is not evidence of physical correctness or authenticity.

The importer keeps uploaded raster bytes and object URLs inside the browser. Only an explicitly saved metric map is passed to the loopback sandbox backend. No image is uploaded to a server or cloud. The JSON and original raster can be downloaded locally. Browser downloads and user scenarios are not repository assets and should remain outside Git by default. JSON imports are limited to 2 MiB. Rasters are limited to 8 MiB, 8192 pixels per axis and 16 megapixels; encoded dimensions are checked before decoding. Static PNG/JPEG/WebP only; SVG, animation, external references and nontrivial JPEG EXIF orientation are rejected. Suggestion work is downsampled to at most 512×512 pixels, emits at most 32 candidates per operation and never exceeds 64 total obstacles. Each ring has at most 256 distinct vertices, with at most 4096 distinct vertices overall.

The suggestion step uses local dark-pixel connected regions and creates **unreviewed bounding outlines**, without hole extraction. It cannot distinguish text, shadows, markings, heights or hidden floor footprints. The wizard permits adding/deleting obstacles, dragging vertices, editing outer/holes numerically, and reviewing each polygon. Prefer verified official drawings/CAD to approximate image extraction when available. No season field dimensions or target heights are invented here.

The geometric planner adapter may conservatively enclose obstacle polygons and fill holes; it must label that conversion and add the robot footprint exactly once. Unsupported nonrectangular boundaries or boundary holes must fail planning closed while remaining viewable. Imported physical geometry never replaces live obstacle observations. Keep the execution guard independent of any sandbox path.
